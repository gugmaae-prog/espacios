A single SQLite Durable Object enforces atomic limits of 3 requests per actor/minute, 10 global/minute, and 40 global/day. Actor identifiers are hashed. Actual remote RPC tests allowed 3 then blocked the fourth actor request, and allowed exactly 10 of 20 concurrent distinct actors. Those tests used isolated validation objects and made no inference calls or production-counter reservations.

The active account catalog and official schema support `@cf/meta/llama-3.1-8b-instruct-fp8` with system/user messages. Successful inference remains **unverified until the account allowance resets**. The public handler now reports this distinct account limit as HTTP 429, `account_free_allowance_reached`, with ISO reset time and `Retry-After` for 00:00 UTC. The application's separate 40-request daily limit has a different error code and Map scope. The existing UI displays the useful JSON error. No further inference calls were made after diagnosis; no upgrade was enabled.

The live project merger currently reads all 46 declared legacy service pages and returns 1,102 actual unique slugs, with `total=1,102`. It separately reports the stale upstream registry count 1,073 and `registryReconciled=false`. It never calls that mismatch proof of missing records. Missing, malformed, changing, or over-budget pages fail with an uncached 503. Only 429/5xx pages receive one retry, with four retries maximum and a hard limit of 50 total fetches; failed bodies are cancelled and each concurrent batch is fully settled. Explicit invalid pagination cannot silently become a single-page success. The final canonical read returned all 46 pages without retry.
