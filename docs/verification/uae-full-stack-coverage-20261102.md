The 1,158 project/source points are retained as reported, not all independently surveyed project sites. The 360 community-centre points indicate approximate areas and must not be used as project-site locations. Together these 1,518 points are renderable on the map; the other 127 records remain searchable.

The V48 record archive has 1,860 project and community records and 16,872 native history series. Its 2,717 approved recovery objects are verified in private IDrive E2 with immutable fallback. This archive does not establish complete current UAE market coverage or recover the original history and saved model bundles.

## Additional source-backed backend data

- [Ajman Real Estate Projects](https://data.ajman.ae/explore/dataset/real-estate-projects/): 3,457 dated snapshot rows, 364 distinct source IDs ever and 298 in the latest 2026-06-30 snapshot. It has no coordinates. Source IDs remain separate from V48 map identities.
- [Ajman Real Estate Units Sales](https://data.ajman.ae/explore/dataset/real-estate-units-sales/): 6,075 quarterly aggregate rows under 239 source project labels. These are not individual transactions.
- [Ajman Real Estate Units Registration](https://data.ajman.ae/explore/dataset/real-estate-units-registration/): 5,124 quarterly aggregate rows under 335 source project labels. Tentative certificates and final title deeds are separate stages and are not added into a unique-unit count.
- [Ajman Real Estate Units Transactions](https://data.ajman.ae/explore/dataset/real-estate-units-transactions/): 6,299 aggregate rows under 249 source labels. This mixes dispositions and mortgage activity without a transaction-type field. It overlaps unit sales, so reported counts cannot be summed. The 318 rows without a reported period and 4,594 rows without monetary values retain nulls. It is served from a checksum-verified immutable Worker asset at `/map/api/uae-evidence/ajman/dispositions`.
- [Ajman Completed Real Estate Development Projects](https://data.ajman.ae/explore/dataset/completed-real-estate-projects/): 496 dated rows and 191 IDs, all already in the Ajman project register with matching dated completed status. It adds zero distinct project identities and is not ingested again.
- [Ajman Management Companies for Real Estate Development Projects](https://data.ajman.ae/explore/dataset/management-companies-for-real-estate-development-projects/): 451 annual appointment rows for 153 exact official Ajman source project IDs, all linked to the separate Ajman project register. Thirteen office IDs appear; three projects have changed offices across 2024–2026. These appointments do not establish developer or owner identity, V48 joins, map coordinates, or current status beyond the latest reported year.
- [Ajman area](https://data.ajman.ae/explore/dataset/ajman-area/): 20 named point references, last modified by the publisher on 3 October 2023. Two independent ordered API reads matched exactly. `/map/api/uae-evidence/ajman/areas` serves them as dated area context, with no project-ID join or change to the V48 project-pin population. The points are not project sites, cadastral boundaries, or verified district centroids.

The Ajman register, unit sales, and unit registrations are stored as separate, checksum-verified private IDrive objects and exposed through read-only, source-labelled APIs. Unit dispositions use a separate immutable Worker asset. The management appointments and area references use checksum-verified embedded snapshots, each with a matching independent API readback. Neither row counts nor project labels can be added to the V48 project total without a reviewed identity crosswalk. The portal's [terms](https://data.ajman.ae/terms/terms-and-conditions.pdf) license its open datasets CC BY 4.0. The APIs are `/map/api/uae-evidence/ajman/register`, `/map/api/uae-evidence/ajman/sales`, `/map/api/uae-evidence/ajman/registrations`, `/map/api/uae-evidence/ajman/dispositions`, `/map/api/uae-evidence/ajman/management`, and `/map/api/uae-evidence/ajman/areas`.

[Ras Al Khaimah Municipality](https://mun.rak.ae/home/rak-municipality/organizational-structure/lands-properties-sector/) publishes historical real-estate transaction reports, and the [RAK Statistics Centre](https://css.rak.ae/en/syvb2026/) publishes annual market aggregates. These are regional summaries, not project-level records or a project denominator. The Municipality's [copyright notice](https://mun.rak.ae/home/open-data/website/copyrights/) prohibits unauthorized reproduction, so no RAK report has been copied into the backend; publication needs a specific reusable dataset or permission.

The newer PSR Data Hub public registry returned 503 on 2 November because Cloudflare D1 rejected reads with free-tier daily row-read error 7500. Read-only D1 exports of the `projects`, `tenant_project_publications`, and `project_registry_state` tables shared bookmark `00000436-00000000-00005117`. The public Data Hub projection from those exports contains 1,091 published PSR projects and unique slugs, matching the recorded registry count and revision 2, updated 27 September 2026. The public projection and its exact checksums are packaged in `data/recovery/psr-public-d1-export-20261102.*`; raw SQL exports remain private. The recorded registry content hash did not reproduce under the current Worker algorithm, so the fallback is labelled degraded with `registryHashReconciled:false` and `completeForCurrentDataHub:false`. If this newer export cannot be verified, the exact older 1,073-slug July snapshot remains a separate degraded fallback. Neither population is the accepted V48 map identity universe or an all-UAE census.

Data Hub v8 adds a checksum-verified read fallback for its **public PSR project endpoints only**: list, detail, manifest and sitemap. Responses include `source.degraded:true`, `completeForCurrentDataHub:false`, `registryHashReconciled:false` and `x-espacios-data-degraded:true`. The fallback preserves the exported 1,091-row ordering and exact public projection; filtered search uses the public projected fields and may differ from live D1 filters where private source fields or overrides differ. It does not serve Haus & Grace, admin writes, pages, developer APIs, or private archives from the PSR snapshot. The temporary `wrangler.data-hub.degraded.jsonc` omits the unusable `ARCHIVES` R2 binding so the Worker can deploy while R2 returns account error 10042. Restricted archive routes still authenticate and then explicitly return 503. Once R2 is enabled, deploy with `wrangler.data-hub.production.jsonc` to restore the binding, then independently verify archive access. The D1 read cache remains in v8 to reduce future reads, but live D1 must be rechecked after quota reset.

Reconcile all live pages, registry totals, and content hash before treating the D1 export as superseded. A paid capacity change requires a separate cost decision.
6. For each new source, capture publisher metadata and licence, preserve immutable source bytes and checksums, validate row grain and quality, publish a source-labelled API, stage at 0%, verify live readback and restrictions, then promote and recheck normal traffic.
